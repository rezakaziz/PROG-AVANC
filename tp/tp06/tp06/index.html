    TP 05 : Le Design Pattern Template Method

    ⬇️ Télécharger le TP (tp06.zip)

    Objectif du TP

    L’objectif de ce TP est de réduire la duplication et de simplifier la structure du code d’accès aux données (DAO) grâce au design pattern comportemental : Template Method.

    Vous allez :

    • identifier le code répétitif dans un DAO naïf ;
    • créer une template factorisant ce comportement ;
    • utiliser une version générique permettant le retour de résultats ;
    • découvrir une version avancée du pattern, déjà implémentée pour vous.

    Instructions préliminaires

    Avant de commencer ce TP, vous devez :

    1. Créer un nouveau dépôt GitHub nommé tp05-template-method.
    2. Ajouter le compte @rezakaziz comme collaborateur.
    3. Cloner votre dépôt et travailler dessus : 
      git add .
git commit -m "progression"
git push
    4. Les tests unitaires doivent continuer à passer après chaque question.

    Note

    Les tests unitaires sont à écrire par l’étudiant lorsqu’ils ne sont pas fournis.

    Exercice 1 :

    Contexte

    On vous fournit un DAO classique, EtudiantDAO, extrêmement verbeux :

    • chaque méthode ouvre une connexion ;
    • crée un PreparedStatement ;
    • exécute du SQL ;
    • ferme la connexion ;
    • gère des exceptions répétitives...

    Si l’on souhaite créer un nouveau DAO ou ajouter un comportement (logging, gestion d’erreur, audit...),
    il faut dupliquer partout, ce qui augmente le risque de bugs.

    ➝ Le but est de factoriser le squelette en créant une classe abstraite selon le pattern Template Method.

    Question 1 — Template sans valeur de retour

    Créez une classe abstraite fournissant une méthode :

    public final void executer() {
    ouvrirConnexion();
    try {
        executerAvecConnexion(connexion);
    } finally {
        fermerConnexion();
    }
}

    Et une méthode à implémenter :

    protected abstract void executerAvecConnexion(Connection c);

    🔧 Travail demandé :

    • Implémenter cette template.
    • Modifier la méthode save(Etudiant e) de EtudiantDAO pour utiliser votre template method.

    Contexte

    On remarque que certaines opérations comme findById(int id) doivent renvoyer un résultat.
    La template précédente ne peut pas être utilisée telle quelle.

    Question 2 — Template générique

    Modifiez votre template pour qu'elle puisse renvoyer une valeur :

    • soit en utilisant le type Object ;
    • soit (plus propre) en la rendant générique

    Une méthode ne renvoyant rien utilisera la classe Void.

    🔧 Travail demandé :

    • Implémenter cette nouvelle version de la template method.
    • Réécrire findById(int id) pour utiliser cette nouvelle template.

    Exercice 2 :

    Contexte

    Le package templateMethod2.template contient une version beaucoup plus avancée du pattern :

    • SQLConnectionTemplate : gestion simple de connexion ;
    • SQLStatementTemplate : permet d’exécuter une requête sur plusieurs jeux de données, avec ou sans retour ;
    • SQLQueryTemplate : gère les SELECT avec extraction d’objet depuis un ResultSet ;
    • SQLSimpleHelper : façade simplifiée servant d’API principale.

    Ces classes reposent sur le même pattern, mais elles encapsulent les détails complexes.

    Question 3 — Réécriture allégée de la DAO

    🔧 Travail demandé :

    • Étudier brièvement les classes ci-dessus :
      commencez par SQLConnectionTemplate, puis SQLStatementTemplate, puis SQLQueryTemplate.
    • Utiliser ensuite SQLSimpleHelper pour réécrire une version beaucoup plus simple de EtudiantDAO.

    Votre objectif :

    • réduire drastiquement la quantité de code ;
    • garder la même logique métier ;
    • faire passer tous les tests existants.
